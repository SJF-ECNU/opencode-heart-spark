# Feature Specification: Personalized Memory System for HeartSpark Companion Mode

**Feature Branch**: `001-personalized-memory`
**Created**: 2026-02-19
**Status**: Draft
**Input**: User description: "为项目添加个性化的记忆系统" - 基于 OpenClaw 记忆系统调研报告

## 背景说明

本功能为 HeartSpark 模拟恋爱模式中的每个角色（Persona）实现个性化记忆系统，使 AI 能够：
- 记住与用户的互动历史
- 保持角色一致性（角色对用户的记忆）
- 提供更真实的情感交互体验

参考设计：OpenClaw 记忆系统调研报告 (`docs/OpenClaw记忆系统调研报告.md`)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 角色记忆文件结构 (Priority: P1)

每个角色（Persona）应该有自己的记忆文件目录结构，包含角色对用户的记忆、角色人格定义、用户信息等核心文件。

**Why this priority**: 这是记忆系统的基础架构，参考 OpenClaw 的文件布局设计，为每个角色建立独立的记忆空间。

**Independent Test**: 可以通过检查每个角色的记忆目录结构来验证。

**Acceptance Scenarios**:

1. **Given** 系统初始化一个新的角色时，**When** 角色目录被创建，**Then** 应该包含 MEMORY.md（长期记忆）、SOUL.md（人格定义）、USER.md（用户信息）、memory/（每日记忆目录）等核心文件
2. **Given** 用户与角色进行对话后，**When** 对话内容应该被记录到 memory/YYYY-MM-DD.md 文件中
3. **Given** 用户分享了重要信息，**When** 角色认为需要永久记住，**Then** 应该写入 MEMORY.md

---

### User Story 2 - 角色对用户的记忆 (Priority: P1)

角色应该记住与用户互动过程中的重要信息，包括用户的喜好、习惯、共同经历等，并在后续对话中自然地提及。

**Why this priority**: 模拟恋爱模式的核心是情感连接，角色记住用户的信息是提供沉浸式体验的基础。

**Independent Test**: 可以在一个会话中告诉角色某些信息，然后在新的会话中验证角色是否记得。

**Acceptance Scenarios**:

1. **Given** 用户告诉角色"我喜欢听你叫我宝贝"，**When** 下次对话时，**Then** 角色应该自然地使用这个称呼
2. **Given** 用户和角色讨论过某个话题（如用户喜欢的电影），**When** 再次提到相关话题时，**Then** 角色应该能够引用之前的讨论
3. **Given** 用户在之前的会话中透露了自己的背景信息（如职业、兴趣），**When** 新会话开始时，**Then** 角色应该展现出对这些信息的了解

---

### User Story 3 - 角色人格记忆 (Priority: P1)

角色应该保持人格一致性，记住自己在之前对话中表达过的观点、态度、情绪反应等。

**Why this priority**: 角色的一致性是模拟真实社交关系的基础，用户不希望角色像失忆症一样每次都重新开始。

**Independent Test**: 可以在不同会话中问角色对同一件事的看法，验证角色的回答是否一致。

**Acceptance Scenarios**:

1. **Given** 角色在之前表示过"不太喜欢用户熬夜"，**When** 用户再次熬夜时，**Then** 角色应该表现出关心的态度
2. **Given** 角色之前对某个话题表达过特定观点，**When** 用户再次提起该话题，**Then** 角色的反应应该与之前一致（除非角色明确改变想法）

---

### User Story 4 - QMD 记忆搜索 (Priority: P2)

系统应该支持基于 QMD 的记忆搜索功能，允许角色通过语义搜索快速找到相关的记忆内容。

**Why this priority**: 随着记忆内容的增加，快速定位相关信息变得重要。QMD 提供 BM25 + 向量混合搜索能力。

**Independent Test**: 可以在记忆库中存储多条不同主题的记忆，然后搜索特定主题来验证检索结果。

**Acceptance Scenarios**:

1. **Given** 角色记忆库中有多条记忆，**When** 用户询问关于某个历史话题，**Then** 系统应该能通过 QMD 搜索找到相关的记忆片段
2. **Given** 用户使用关键词搜索，**When** QMD 应该支持 BM25 精确匹配
3. **Given** 用户使用语义描述搜索，**When** QMD 应该支持向量相似度搜索

---

### User Story 5 - 记忆自动刷新机制 (Priority: P2)

当会话上下文即将被压缩之前，系统应该触发记忆刷新机制，确保重要信息被写入持久存储。

**Why this priority**: 参考 OpenClaw 的 Pre-compaction Ping 机制，防止重要记忆因上下文压缩而丢失。

**Independent Test**: 可以通过模拟上下文压缩场景来验证记忆是否被正确保存。

**Acceptance Scenarios**:

1. **Given** 会话token接近上下文窗口限制，**When** 系统触发压缩前提醒，**Then** 角色应该将重要的短期记忆写入持久存储
2. **Given** 用户没有提供任何重要信息，**When** 触发记忆刷新，**Then** 角色应该回复静默信号（如 NO_REPLY）表示无需保存

---

### User Story 6 - 用户记忆管理 (Priority: P2)

用户应该能够查看、导出或删除角色对自己的记忆，保持对个人数据的控制。

**Why this priority**: 隐私保护是重要原则，用户有权管理自己的数据。

**Acceptance Scenarios**:

1. **Given** 用户想查看角色对自己的了解程度，**When** 用户请求查看记忆，**Then** 系统应该以可读格式展示所有记忆
2. **Given** 用户想导出记忆备份，**When** 用户请求导出，**Then** 系统应该生成记忆文件的压缩包
3. **Given** 用户想删除特定记忆，**When** 用户请求删除，**Then** 系统应该删除对应记忆并确认

---

### User Story 7 - 主动记忆刷新命令 (Priority: P1)

用户应该能够通过命令主动触发记忆刷新，将当前会话中的重要信息保存到持久存储。

**Why this priority**: 用户可能希望在任何时候主动保存重要信息，而不是依赖自动触发机制。这提供了更直接的用户控制体验。

**Independent Test**: 可以通过执行命令来验证当前会话的对话是否被正确保存到记忆文件中。

**Acceptance Scenarios**:

1. **Given** 用户在对话中分享了重要信息，**When** 用户执行刷新记忆命令，**Then** 系统应该将当前会话的重要信息写入 MEMORY.md 或当日记忆文件
2. **Given** 用户执行刷新命令但没有重要信息需要保存，**When** 命令执行后，**Then** 系统应该告知用户没有新的重要信息需要保存
3. **Given** 用户想指定保存哪些内容，**When** 用户提供具体内容，**Then** 系统应该只保存用户指定的内容

---

### Edge Cases

- 当角色记忆文件损坏或无法读取时如何处理？
- 当多个角色共享同一用户时，如何隔离每个角色的记忆？
- 当用户希望角色"忘记"某些事情时，如何实现选择性遗忘？
- 当 QMD 搜索失败时，系统是否回退到其他搜索方式？
- 角色是否应该记住用户明确要求忘记的事情？

---

## Requirements *(mandatory)*

### Functional Requirements

#### 记忆文件结构 (Memory File Structure)

- **FR-001**: 系统必须为每个角色（Persona）创建独立的记忆目录
- **FR-002**: 角色记忆目录必须包含 MEMORY.md（长期记忆）、SOUL.md（人格定义）、USER.md（用户信息）
- **FR-003**: 角色记忆目录必须包含 memory/ 子目录用于存储每日记忆文件
- **FR-004**: 每日记忆文件必须遵循 YYYY-MM-DD.md 命名规范
- **FR-005**: 系统必须在会话初始化时加载角色的人格定义和用户信息

#### 角色记忆功能 (Character Memory)

- **FR-006**: 系统必须自动存储角色与用户对话中的重要信息
- **FR-007**: 系统必须在会话开始时加载该角色的历史记忆
- **FR-008**: 系统必须在用户明确要求时永久保存特定记忆到 MEMORY.md
- **FR-009**: 系统必须支持角色对用户记忆的时间衰减（近期记忆权重更高）

#### QMD 搜索功能 (QMD Search)

- **FR-010**: 系统必须支持 QMD 后端的 BM25 关键词搜索
- **FR-011**: 系统必须支持 QMD 后端的向量语义搜索
- **FR-012**: 系统必须支持 QMD 混合搜索模式（BM25 + Vector + Rerank）
- **FR-013**: 当 QMD 不可用时，系统必须回退到内置搜索方案
- **FR-014**: QMD 搜索结果必须包含来源文件和行号引用

#### 记忆刷新机制 (Memory Flush)

- **FR-015**: 系统必须在会话接近上下文限制前触发记忆刷新提醒
- **FR-016**: 刷新机制应该静默执行（不打扰用户）
- **FR-017**: 系统必须支持将短期记忆（当日日志）提取到长期记忆（MEMORY.md）

#### 用户控制功能 (User Control)

- **FR-018**: 系统必须允许用户查看角色对自己的所有记忆
- **FR-019**: 系统必须允许用户导出记忆数据
- **FR-020**: 系统必须允许用户删除特定记忆
- **FR-021**: 系统必须提供主动记忆刷新命令供用户触发
- **FR-022**: 记忆刷新命令必须支持指定保存内容
- **FR-023**: 记忆刷新命令执行后必须返回执行结果确认

### Key Entities

- **角色记忆目录 (Character Memory Directory)**: 每个角色独立的记忆存储空间，路径格式为 `~/.heartspark/personas/<persona_id>/memory/`
- **MEMORY.md**: 长期记忆文件，存储持久化的事实、偏好、决策
- **SOUL.md**: 角色人格定义文件，包含角色的性格、语气、边界
- **USER.md**: 用户信息文件，记录用户的基本信息、偏好、背景
- **memory/YYYY-MM-DD.md**: 每日记忆文件，记录当日的对话和重要事件
- **QMD Index**: QMD 搜索索引，包含 BM25 索引和向量嵌入

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 角色能在新会话开始后5秒内加载并准备好历史记忆
- **SC-002**: 90%的情况下，角色能正确回忆用户在之前会话中分享的重要信息
- **SC-003**: 记忆存储操作（写入、读取）在1秒内完成
- **SC-004**: 85%的用户认为角色具有"记忆力"，对话更加个性化
- **SC-005**: QMD 搜索能在2秒内返回相关记忆结果
- **SC-006**: 系统能够在上下文压缩前成功保存95%的临时重要记忆
- **SC-007**: 用户能够成功导出和查看角色对自己的所有记忆
- **SC-008**: 主动记忆刷新命令在2秒内完成执行并返回结果

---

## Assumptions

- 每个角色（Persona）有独立的记忆存储空间，角色之间记忆隔离
- 记忆数据持久化存储，不会因应用关闭而丢失
- 系统有足够的存储容量（每个角色约 100-500 条记忆）
- 用户接受角色记住自己的偏好和互动历史
- 角色人格定义（SOUL.md）在会话间保持稳定
- 参考 OpenClaw 的工作区布局设计记忆文件结构
